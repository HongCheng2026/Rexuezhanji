# 战斗系统与养成联动拆分方案

## 目标

本方案用于后续重构 `src/h5/game.js` 内部结构。当前阶段只面向本地部署测试，不处理线上部署、域名、Netlify 发布流程，也不同步重构微信/抖音小程序工程。

本次改造目标是：

- 将战斗主循环、玩家、武器、敌军、BOSS、掉落、碰撞、战斗剧情和结算从 `game.js` 中拆成清晰模块。
- 将养成系统中的战姬、战机、大厅强化、战机强化统一转换成战斗可用属性。
- 点击大厅“开始战斗”后先进入关卡选择面板，选择关卡后再开始战斗。
- 关卡选择面板左上角显示玩家战斗属性，从上到下依次为生命、攻击、破甲。
- 本地测试阶段解锁所有关卡，但不默认标记全部已通关。
- 敌军属性和改动统一接入战斗系统，避免敌军数据表和实际战斗表现脱节。

## 架构原则

养成系统和战斗系统之间必须通过“出战属性快照”连接。

战斗系统不直接读写完整 `profile`，也不散着读取 `profile.scene`、`profile.upgrades`、`profile.fighterUpgrades`。养成系统先生成 `BattleLoadout`，战斗系统只消费这个快照。

战斗系统只产出 `BattleResult`，不直接修改金币、经验、关卡进度、通关星级或云存档。结算、存档和云端同步交给养成/存档层处理。

## 模块边界

### battle/

`battle/` 负责战斗运行时，不负责长期存档。

建议模块：

- `battleRuntime.js`：战斗生命周期、主循环、暂停、恢复、胜负状态切换。
- `battleState.js`：创建和重置战斗状态。
- `playerSystem.js`：玩家移动、生命、护盾、无敌时间、出战属性应用。
- `weaponSystem.js`：普通射击、三种武器、融合武器、武器名称显示数据。
- `projectileSystem.js`：我方子弹、敌方子弹、导弹追踪、弹道更新。
- `enemySystem.js`：小怪/精英怪生成、移动、开火、运行时属性。
- `bossSystem.js`：BOSS 生成、移动、攻击、阶段行为。
- `collisionSystem.js`：子弹命中、玩家受伤、拾取判定、敌军死亡判定。
- `dropSystem.js`：金币、道具、掉落概率、吸附逻辑。
- `battleStoryRuntime.js`：战斗内剧情触发、显示时长、非阻塞播放状态。
- `settlementSystem.js`：根据战斗状态生成 `BattleResult`。

### meta/

`meta/` 负责养成、存档、进度和战斗前后的数据转换。

建议模块：

- `profileRuntime.js`：本地存档读取、保存、恢复、云同步入口。
- `combatStats.js`：将 `profile`、战姬、战机、强化转换成 `BattleLoadout`。
- `progressionSystem.js`：关卡解锁、通关记录、星级、扫荡资格。
- `upgradeSystem.js`：大厅强化和战机强化的等级、费用、属性增益。
- `shopSystem.js`：商城购买与资源变化。
- `taskRuntime.js`：任务进度更新。
- `achievementRuntime.js`：成就进度更新。

### ui/

`ui/` 负责 DOM 和显示，不负责战斗规则。

建议模块：

- `lobbyView.js`：大厅资源、玩家头像、战姬/战机/背景展示。
- `battleHudView.js`：关卡、时间、生命、金币、武器名称、BOSS 提示。
- `chapterSelectView.js`：关卡选择面板、章节页签、玩家属性面板。
- `featurePanelView.js`：功能面板。
- `shopView.js`：升级和商城界面。
- `assetSelectorView.js`：战姬、战机、背景选择。

## 关键接口

### BattleLoadout

`BattleLoadout` 是养成进入战斗的唯一数据入口。

建议结构：

```js
{
  pilot: {
    id,
    name,
    rank,
    damage,
    armorPenetration,
    avatarSrc
  },
  ship: {
    id,
    name,
    rank,
    damage,
    hp,
    armorPenetration,
    src
  },
  upgrades: {
    fire,
    armor,
    engine,
    bounty
  },
  fighterUpgrades: {
    attack,
    armorPenetration,
    hp
  },
  finalStats: {
    maxLives,
    attack,
    armorPenetration,
    moveSpeed,
    coinBonus,
    weaponDamageMultiplier
  },
  initialWeapons: {
    spread,
    laser,
    missile
  }
}
```

关卡选择面板左上角显示的生命、攻击、破甲必须来自 `BattleLoadout.finalStats`。

### BattleResult

`BattleResult` 是战斗结束时传给结算/存档层的数据。

建议结构：

```js
{
  isWin,
  levelId,
  chapterIndex,
  stageInChapter,
  killedEnemies,
  totalEnemies,
  coinsEarned,
  damageTaken,
  powerupsSpawned,
  powerupsCollected,
  bossClearTime,
  rating
}
```

`battle/` 只生成这个结果，不直接保存。

### EnemyRuntimeStats

敌军运行时属性由 `enemyStageBalance.js` 和当前关卡共同生成。

建议结构：

```js
{
  enemyType,
  name,
  hp,
  maxHp,
  damage,
  moveSpeed,
  radius,
  canFire,
  firstFireDelay,
  fireInterval,
  bulletSpeed,
  bulletPattern,
  damageReductionRate,
  damageTakenMultiplier,
  coinValue
}
```

战斗中的刷怪、敌军血量、减伤、速度、开火、BOSS 属性优先使用 `enemyStageBalance.js`，不再由旧的 `level.spawn` 和 `level.eliteRate` 主导。

## 战斗流程

建议流程：

```text
大厅点击开始战斗
  -> 打开关卡选择面板
  -> meta/combatStats 生成 BattleLoadout
  -> 面板左上角显示生命、攻击、破甲
  -> 玩家选择关卡
  -> 点击开始关卡
  -> battleRuntime.start({ level, loadout, assets, callbacks })
  -> 战斗系统运行
  -> settlementSystem 生成 BattleResult
  -> meta/progressionSystem 和 profileRuntime 处理奖励、经验、通关进度
  -> UI 刷新大厅、关卡选择、结算面板
```

## 剧情与敌军数据归属

剧情配置和战斗内播放需要分离：

- 剧情配置继续由共享配置或内容配置保存。
- 战斗内剧情触发、消息显示时间、是否阻塞输入、当前显示状态属于 `battle/battleStoryRuntime.js`。

敌军数据和敌军运行时也需要分离：

- 敌军基础数据、章节难度、关卡敌军组成、BOSS 配置来自 `enemyStageBalance.js`。
- 敌军生成、移动、开火、死亡、掉落属于 `battle/enemySystem.js` 和 `battle/bossSystem.js`。

## 本地测试要求

本次只做本地测试。

要求：

- 增加本地测试开关，例如 `LOCAL_TEST_UNLOCK_ALL_LEVELS = true`。
- 本地读取/创建存档后，将 `profile.unlockedLevel` 设置为 `levels.length`。
- 只解锁所有关卡，不自动把所有关卡写入 `profile.completed`。
- 扫荡、星级、通关记录仍然以真实通关结果为准。
- 本次不要求部署到 Netlify，不要求修改域名，不要求改 Supabase 服务端。
