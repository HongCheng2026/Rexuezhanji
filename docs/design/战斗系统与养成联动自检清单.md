# 战斗系统与养成联动自检清单

- [ ] 确认本次只改 H5 本地测试代码，不改线上部署流程。

- [ ] 确认拆分前已记录 `game.js` 中战斗、养成、UI、存档相关函数的位置。

## 代码结构检查

- [ ] 已新增 `battle/` 目录并承接战斗运行时逻辑。
- [ ] 已新增或使用 `meta/` 目录承接养成、存档、进度、战斗属性转换逻辑。
- [ ] 已新增或使用 `ui/` 目录承接大厅、关卡选择、战斗 HUD、功能面板显示逻辑。
- [ ] `game.js` 不再作为所有战斗逻辑的堆放文件。

- [ ] UI 模块不直接计算战斗公式。

## 战斗流程检查

- [ ] 点击大厅“开始战斗”后，进入关卡选择面板，而不是直接进入战斗。
- [ ] 选择关卡后，开始按钮文本能正确反映当前关卡。
- [ ] 点击开始关卡后，才进入 Canvas 战斗。
- [ ] 暂停、继续、重开、返回大厅仍可用。
- [ ] 胜利后进入结算流程。
- [ ] 失败后进入失败流程。
- [ ] 结算后可以再次挑战当前关卡。
- [ ] 返回大厅后，战斗状态被正确重置。

## 关卡选择 UI 检查

- [ ] 关卡选择面板左上角显示玩家属性面板。
- [ ] 属性顺序从上到下为生命、攻击、破甲。
- [ ] 生命显示来自 `BattleLoadout.finalStats.maxLives`。
- [ ] 攻击显示来自 `BattleLoadout.finalStats.attack`。
- [ ] 破甲显示来自 `BattleLoadout.finalStats.armorPenetration`。
- [ ] 更换战姬后，关卡选择面板属性会刷新。
- [ ] 更换战机后，关卡选择面板属性会刷新。
- [ ] 升级强化后，关卡选择面板属性会刷新。
- [ ] 面板不遮挡关卡列表、章节页签和开始按钮。
- [ ] 移动端视口下属性面板不与按钮、文字重叠。

## 养成联动检查

- [ ] 已建立 `BattleLoadout` 或等价出战属性快照。

- [ ] 战机攻击会影响 `finalStats.attack`。
- [ ] 战机生命或耐久会影响 `finalStats.maxLives` 或等价生命属性。
- [ ] 战机破甲会影响 `finalStats.armorPenetration`。
- [ ] 大厅强化 `fire` 会影响武器伤害或初始武器等级。
- [ ] 大厅强化 `armor` 会影响生命。
- [ ] 大厅强化 `engine` 会影响移动速度。
