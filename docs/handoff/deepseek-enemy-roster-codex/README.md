# DeepSeek 交接：93 关敌军阵容、战斗与图鉴重构

## 先读什么

开始修改前，必须按顺序完整阅读：

1. 项目根目录 `AGENTS.md`
2. `docs/handoff/agent-context.md`
3. 本文件
4. `01-content-catalog.md`
5. `02-technical-implementation.md`
6. `03-art-runtime-contract.md`
7. `04-acceptance-checklist.md`

如果任务文档与根目录 `AGENTS.md` 冲突，以 `AGENTS.md` 为准；如果现有代码与文档描述不同，先查清差异并在完工报告中说明，不得静默删减需求。

## 一句话目标

把当前“少量泛型敌机反复换名字”的实现，改成由 **80 个常规敌军单位、93 个关卡专属 BOSS、93 份关卡出战表**驱动的真实单位系统，并让战斗、关卡情报、图鉴和我方战机名称使用同一数据来源。

## 已确认的现状

- 游戏共有 93 关：序章 3 关，第一章至第九章各 10 关。
- `src/shared/assets.js` 当前图鉴只有 9 条泛型敌机记录。
- 战斗中的 `small` 当前只绑定一张主要侦察机素材；不能通过增加多个名字假装成多个小怪。
- 当前战斗底层以 `enemyType` 表示数值和攻击大类，缺少表示真实兵种身份的 `unitId`。
- 当前 BOSS 主要按章节共用标题、主题和造型，尚未形成 93 个关卡级 BOSS。
- `SHIP_ASSETS` 已包含 9 架我方战机的正式名字，但部分页面仍有手写名称。

## 本次代码交付范围

必须完成：

- 新增一个统一的敌军资料模块。
- 建立 30 个小怪、30 个普通敌机、20 个精英敌机，共 80 个常规敌军配置。
- 建立 93 个 BOSS 配置，每关一个唯一 `bossId`。
- 建立 93 份逐关出战表，每关实际出现 2–3 种小怪、1–3 种普通敌机、0–2 种精英和 1 个 BOSS。
- 战斗生成器只能从当前关卡出战表中选择单位。
- 不同单位具有不同的移动、攻击或支援配置；允许复用底层处理函数，但不能 80 个单位只换名称。
- BOSS 名称、造型元数据和攻击组合按关卡读取，不再只在章节第 10 关区分。
- 图鉴按章节和关卡展示真实阵容。
- 关卡详情中的主要敌军改为真实阵容。
- 9 架我方战机名称统一从 `SHIP_ASSETS` 查询。
- 增加 `node:test` 自动测试并保持现有测试通过。

本轮不要求完成：

- 173 张最终敌军美术。
- 发布上线。
- 小程序平台手工改动。
- 存档结构迁移。

## 占位美术不是最终美术

本轮允许不同单位暂时复用现有战斗图，但必须同时满足：

- 每个单位都预留独立美术槽位和未来路径。
- 使用 `artStatus: "placeholder"` 明确标记。
- 当前运行时只能加载真实存在的文件；未来文件不存在时必须走 `fallbackAssetId`。
- 不得把不存在的文件路径写进 `<img src>` 或 Canvas 预加载流程制造 404。
- 完工报告必须单列占位素材，不能宣称最终造型已完成。

详细约束见 `03-art-runtime-contract.md`。

## 不可降低的内容标准

- 不是“每关一种小怪”。
- 不是“每关四个阵容总称”。
- 不是 80 个名字映射到同一个 `small` 行为。
- 同一种兵种跨关复用时保持同一名字和 `unitId`。
- 每个 BOSS 只属于一个 `stageId`。
- 第九章必须按“三海草母 → 弥赛亚近卫/意识海 → 弥赛亚机甲 → 黑潮女王·弥赛亚”的剧情层级推进。
- 本文档中的名称是审核稿真相源，未经用户重新审核不得自行改名。

## 修改边界

- 共享数据、关卡阵容、敌军资料：`src/shared/`
- H5 战斗、渲染、图鉴和选关：`src/h5/`
- 测试：`tests/`
- 最终运行时素材未来放在 `assets/runtime/`，本轮不存在的素材不得提前创建虚假路径引用。
- 禁止直接修改 `release/`。
- 禁止直接修改微信、抖音平台镜像；共享层最终通过 `scripts/sync-release.ps1` 同步。
- 不主动读取或修改 `archive/`、`docs/chat-backups/`、`assets/originals/`、`assets/references/`、日志文件。
