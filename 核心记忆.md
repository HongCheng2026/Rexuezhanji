## Mini Program Multi-Platform Plan

- The project is expected to support both WeChat Mini Program and Douyin Mini Program.
- Keep platform-neutral game logic in a shared layer whenever possible.
- Use this default structure for mini program work:
  - `mini-shared/`: shared game configuration, battle rules, player profile logic, economy rules, level data, enemy data, reward data, and other platform-neutral JavaScript.
  - `wechat-miniprogram/`: WeChat-specific pages, WXML, WXSS, `wx.*` platform APIs, WeChat payment, WeChat login, WeChat sharing, WeChat ads, and WeChat developer tool configuration.
  - `douyin-miniprogram/`: Douyin-specific pages, TTML, TTSS, `tt.*` platform APIs, Douyin payment, Douyin login, Douyin sharing, Douyin ads, and Douyin developer tool configuration.
- Prefer changing shared game behavior in `mini-shared/` first, then adapt the platform shells only when platform APIs or markup require it.
- Do not duplicate core game rules separately inside `wechat-miniprogram/` and `douyin-miniprogram/` unless there is a clear platform-specific reason.
- Avoid scattering raw `wx.*` or `tt.*` calls through reusable logic. Wrap platform APIs in small platform adapters when shared code needs navigation, storage, payment, ads, login, or sharing.
- Reusable between WeChat and Douyin:
  - player profile data
  - energy, gold, diamond resource rules
  - experience, level, and badge calculation
  - level configuration
  - enemy and boss configuration
  - upgrade rules
  - reward and drop rules
  - battle math, collision rules, scoring, and win/loss settlement
  - local save data shape
- Platform-specific and not directly reusable:
  - page markup (`.wxml` for WeChat, `.ttml` for Douyin)
  - page styles (`.wxss` for WeChat, `.ttss` for Douyin)
  - platform API calls (`wx.*` vs `tt.*`)
  - payment
  - ads
  - login and authorization
  - sharing and social features
  - platform review and project configuration
- When adding new features, first decide whether the feature belongs in shared game logic or platform shell. Put it in shared logic if it affects rules, data, rewards, progression, or battle behavior. Put it in the platform shell if it affects UI markup, platform capability, payment, ads, login, sharing, or review configuration.
